# Support Guidelines

Thank you for using this project! Before seeking support, please review the resources below to find the help you need.

## 📖 1. Documentation & Search

Before reaching out, check if your question or issue is already addressed:

* **Project Documentation:** Review the `README.md` or the official documentation.
* **Search Existing Issues:** Check both open and closed [GitHub Issues](../../issues) to see if someone else has already encountered and resolved the same question.

## ❓ 2. Getting Help & Asking Questions

For "How-To" questions, configuration guidance, or general inquiries:

* **Issue Tracker:** If discussions are not active, you can open an issue with a clear label describing your question.

Please provide sufficient context when asking a question, including:

* Your operating system / environment details.
* The version of the tool or package you are using.
* Relevant code snippets or configuration files (with sensitive data removed).

## 🐛 3. Reporting Bugs or Unexpected Behavior

If you encountered a bug or error:

1. Open a new [GitHub Issue](../../issues/new/choose).
2. Use the **Bug Fix** template if available.
3. Include clear steps to reproduce the issue, expected outcome, and actual error logs.

## 🔐 4. Security Concerns

For security vulnerabilities or sensitive issues, please **do not** create a public issue.
Refer to our [SECURITY.md](SECURITY.md) for instructions on how to submit a private security report.
